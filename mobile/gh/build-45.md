## A. 键盘弹出又收回，版面塌了 + 进度掉回 7%

用户截图：正文挤在上半屏、最后一截被裁掉、下面一大片空白，翻页也不恢复，
阅读进度从中间掉回 7%。

| 根因 | 说明 |
|---|---|
| 几何 | `renderTo` 传的是 `width:'100%'`，epub.js 因此**自己监听 `window.resize`**（50ms 防抖）。键盘弹起 → 按矮版重排，内部 `_stageSize` 更新成矮版 |
| 事件缺失 | **键盘收起时安卓 WebView 不一定派发 `resize`** → epub.js 以为尺寸还是矮的，iframe 停在矮版高度。翻页只移动列、不重算 columns 高度，所以「翻页也改不回来」 |
| 没补 display | `resize()` 只 `clear()` + 发一个事件，**不会自己 `display`** —— 判「无需处理」必须同时看「有内容」与「位置对」 |
| 进度 | 重排照发 `relocated`，700ms 后落盘，把读者真正的进度顶掉 |

现在：判据从「有没有收到事件」改成「容器尺寸和上次看到的是不是一样」；
三条触发（`window.resize` / `orientationchange` / **`visualViewport.resize`**）
外加 **900ms 轮询兜底**；锚点用「几何稳定时的位置快照」；
几何在变时 `relocated` 只重画标记、不动进度账本，落盘推迟（上限 6 拍）。

- [ ] 在阅读中打开任意输入框（词卡「换个词重查」/ 生词搜索 / 词条编辑），
      弹一次键盘再收起 → 正文版面**不变**，不出现「下半屏空白 + 最后一截被裁」
- [ ] 收起键盘后翻一页 → 正常；再翻回来 → 正常
- [ ] 底部进度条**不跳**（不再出现「从中间掉回 7%」）
- [ ] 转一下手机再转回来（如果那台机器没锁竖屏）→ 版面与位置都对
